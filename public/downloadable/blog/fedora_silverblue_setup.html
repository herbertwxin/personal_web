Fedora Silverblue Setup Guide

Post-install steps for an immutable, economist-oriented workstation
Version: Fedora Silverblue 39 Scope: Flatpak · Toolbox · Layering · Nvidia · MATLAB · Dynare · LaTeX
Abstract

Fedora Silverblue's immutable design changes how applications and packages are installed: / and /usr are read-only, so the familiar dnf install workflow no longer applies. This guide collects the post-install steps I take to turn a fresh Silverblue system into a usable, economist-oriented workstation — covering the three installation mechanisms (Flatpak, Toolbox, layering), Nvidia/graphics configuration, and the trickier setups for MATLAB, Dynare, and LaTeX under an immutable filesystem. Many ideas are adapted from Willi Mutschler's Workstation guide, but the immutable nature of Silverblue requires a different approach throughout.

Note Feel free to contact me if you have any question with these instructions — either through email or on the website's GitHub repository. The version used is Fedora Silverblue 39 at the time of writing, and most of the software here is fairly personal and economist-oriented.
1 Background: How Silverblue Differs

Silverblue differs from normal Fedora Workstation in that it is immutable: system files are read-only and updates are installed as a whole. More technically, /, /usr, and everything below them are read-only, while everything under /var is user-changeable. For more information, consult the Fedora Docs.

This means Silverblue installs applications and packages differently from Workstation — dnf install will not work. There are three ways to do it.

Flatpak

Flatpak is the predominant way to install applications, as it places each application into a sandbox, aligning with the immutable approach of Silverblue. It is generally recommended to add the Flathub repo to gain access to more applications; for instructions, consult the Fedora Docs.

Toolbox

Toolbox creates an isolated container in which to install packages and software. It is almost like an emulator of the host system — a self-contained system attached to the host. To create a toolbox:

create toolbox --container [name of container]

After entering the toolbox:

toolbox enter [name of container]

Inside it you can use the normal Fedora/RHEL commands.

Layering

Layering goes against the immutable approach of the system, but many packages benefit from it because they are layered onto the system and have a more direct connection with it. I recommend layering only essential packages, like graphics card drivers. To layer a package onto the system:

rpm-ostree install [package name]

To uninstall a layered package:

rpm-ostree uninstall [package name]
2 Graphics

Wayland & Xorg

Fedora uses Wayland as the default and will gradually deprecate Xorg, but in practice the experience can be quite poor with an Nvidia card whose drivers are not properly set up. Recent advances from Nvidia have made Wayland quite usable, provided you install all the drivers.

Use Xorg

Using an Xorg session, I can solve most display issues with VSCode and Obsidian (both installed through Flatpak). To use Xorg instead of Wayland, uncomment WaylandEnable=false and add DefaultSession=gnome-xorg.desktop to the [daemon] section of /etc/gdm/custom.conf:

sudo nano /etc/gdm/custom.conf
# [daemon]
# WaylandEnable=false
# DefaultSession=gnome-xorg.desktop

# Cuda libs for Xorg
rpm-ostree install xorg-x11-drv-nvidia-cuda
rpm-ostree install xorg-x11-drv-nvidia-cuda-libs

Then reboot for the change to take effect.

Nvidia & Wayland

To install the proprietary Nvidia driver:

rpm-ostree update

# Nvidia proprietary driver
rpm-ostree install akmod-nvidia

# The Nvidia proprietary driver doesn't support VAAPI, but there is a
# wrapper that can bridge NVDEC/NVENC with VAAPI
rpm-ostree install nvidia-vaapi-driver

# Provides more codecs for video streaming
rpm-ostree install libavcodec-freeworld

After all the installations, follow the instructions and reboot the system:

systemctl reboot
3 Software

Foliate

I really like this handy app for reading my .epub books, but it has some trouble accessing the graphics card, resulting in pages that don't render properly. The issue mostly comes down to a lack of permission. The simplest fix is to disable GPU acceleration for Foliate:

  1. Install Flatseal either via the GUI or the command line.
  2. Disable the GPU acceleration option for Foliate.
  3. Problem fixed!

Since Foliate is not very demanding, even without GPU acceleration it runs smoothly enough that I have not looked for other solutions.

MATLAB

Installation

Always refer to the official installation guide for more info. After downloading the MATLAB installation file, unzip it with:

unzip matlab_R2023b_glnxa64.zip -d matlab_R2023b_glnxa64

Navigate to the matlab_R2023b_glnxa64 directory and launch the installer with:

./install

Install MATLAB under the /var directory so you have full permission. I recommend installing it to /var/home/$USER/bin.

Desktop Entry

Here is a reference for the desktop entry:

[Desktop Entry]
Version=1.0
Type=Application
Terminal=false
Exec=/var/home/$USER/bin/MATLAB/R2023b/bin/matlab -desktop
Name=MATLAB R2023b
Icon=/var/home/$USER/bin/MATLAB/bin/glnxa64/cef_resources/matlab_icon.png
Categories=Development;Math;Science
Comment=Scientific computing environment
StartupNotify=true
StartupWMClass=sun-awt-X11-XFramePeer
MimeType=text/x-matlab

Libraries

Although Willi Mutschler suggests it is better to use system libraries instead of MATLAB's shipped ones, this is not the case under Silverblue: MATLAB does not have access to system-level files and cannot use the system libraries. There is therefore no need to exclude the packages shipped with MATLAB — in fact, you need to copy some packages from the system into the MATLAB directories for Dynare to work properly, since it cannot access system-level files either.

Dynare

Dynare needs to be compiled from source on a Fedora-based system, and the method is slightly different under Silverblue.

Fundamental packages

To compile Dynare we need several packages. I recommend installing these inside a toolbox to align with the immutable approach.

toolbox create --container Dynare-compile
# Enter the toolbox
toolbox enter Dynare-compile

Install all the packages inside this toolbox:

# Minimal packages (use --disable-doc and --disable-octave flags)
sudo dnf install -y gcc gcc-g++ gfortran boost-devel gsl-devel lapack \
  lapack-devel matio-devel openblas openblas-devel suitesparse-devel \
  bison flex make autoconf automake redhat-rpm-config
# Octave packages (use --disable-doc flag)
sudo dnf install -y octave octave-devel octave-statistics octave-io \
  octave-optim octave-control
# Documentation packages
sudo dnf install -y texlive-scheme-minimal texlive-collection-publishers \
  texlive-collection-latexextra texlive-collection-fontsextra \
  texlive-collection-latexrecommended texlive-collection-science \
  texlive-collection-plaingeneric texlive-lm python3-sphinx latexmk \
  mathjax doxygen

Next, compile slicot and x13as. The code below is adapted from the Dynare compiling instructions for Fedora, CentOS or RHEL.

# compile slicot from source and put it into /home/$USER/dynare/slicot/lib/
mkdir -p /var/home/$USER/dynare/slicot
cd /var/home/$USER/dynare/slicot
wget https://deb.debian.org/debian/pool/main/s/slicot/slicot_5.0+20101122.orig.tar.gz
tar xf slicot_5.0+20101122.orig.tar.gz
cd slicot-5.0+20101122
make FORTRAN=gfortran OPTS="-O2 -fPIC -fdefault-integer-8" LOADER=gfortran lib
mkdir -p /var/home/$USER/dynare/slicot/lib
cp slicot.a /var/home/$USER/dynare/slicot/lib/libslicot64_pic.a # for MATLAB
cp slicot.a /var/home/$USER/dynare/slicot/lib/libslicot_pic.a   # for octave

# compile x13as from source and put it into /usr/bin/
mkdir -p /var/home/$USER/dynare/x13as
cd /var/home/$USER/dynare/x13as
wget https://www2.census.gov/software/x-13arima-seats/x13as/unix-linux/program-archives/x13as_asciisrc-v1-1-b60.tar.gz
tar xf x13as_asciisrc-v1-1-b60.tar.gz
sed -i "s|-static| |" makefile.gf  # removes '-static' in makefile.gf
make -f makefile.gf FFLAGS="-O2 -std=legacy" PROGRAM=x13as
sudo cp x13as /usr/bin/

Compile Dynare

Once the prerequisite packages are sorted, we can start compiling Dynare.

cd /var/home/$USER/dynare
# This uses the current unstable branch
git clone --recurse-submodules https://git.dynare.org/dynare/dynare.git unstable
cd unstable
# Direct Dynare to your MATLAB path
meson setup -Dmatlab_path=/var/home/$USER/bin/MATLAB \
  -Dfortran_args="[ '-B', '/var/home/$USER/dynare/slicot/lib']" \
  -Dbuildtype=debugoptimized build-matlab
meson compile -C build-matlab
ninja -C build-matlab
meson install -C build-matlab

This gives you a nearly working Dynare, except that it now needs the latest libstdc++.so.6 and libstdc++.so.6.0.32 packages shipped with the system. As mentioned earlier, Silverblue prevents MATLAB from using the system-shipped packages, so we rely on the ones shipped with MATLAB.

To do this, first move the libstdc++.so.6 and libstdc++.so.6.0.32 packages that came with MATLAB into an exclude folder, then copy in the ones from our system:

export MATLAB_ROOT=/var/home/$USER/bin/MATLAB
cd /var/home/$USER/bin/MATLAB/sys/os/glnxa64
mkdir -p exclude
mv libstdc++* exclude/
cd /lib64
cp libstdc++.so.6 /var/home/$USER/bin/MATLAB/sys/os/glnxa64
cp libstdc++.so.6.0.32 /var/home/$USER/bin/MATLAB/sys/os/glnxa64

This should give you a running Dynare; simply add Dynare to the path inside MATLAB afterward.

LaTeX

I use LaTeX with VSCode for all my writing, but this combination is a bit harder under Silverblue. My approach is to install LaTeX in a toolbox and then let VSCode (and LaTeX Workshop) communicate with the LaTeX stored inside the toolbox.

Install TeX Live

# Create the LaTeX container
toolbox create --container LaTeX
toolbox enter LaTeX

# Add the TeX Live repository if needed
sudo dnf config-manager --add-repo https://mirrors.tuna.tsinghua.edu.cn/texlive/fedora/

# Install the packages
sudo dnf install texlive texlive-scheme-full texlive-extra-utils

# Update the packages
sudo dnf update texlive*

# Verify the installation
tex --version

VSCode & the LaTeX Workshop extension

Install VSCode via Flatpak — the community-maintained version works fine for me, though you could install the official one through layering or a toolbox. After installing VSCode, use the extension marketplace to install the LaTeX Workshop extension.

Once LaTeX Workshop is installed, configure it so it can communicate with the LaTeX inside the toolbox by editing VSCode's settings.json. The key idea is to route every tool command through host-spawn into the LaTeX container:

// Only if you use the LaTeX Utilities extension for word count etc.
"latex-utilities.countWord.path": "host-spawn",
"latex-utilities.countWord.args": ["toolbox", "run", "--container", "LaTeX", "texcount"],

// Required for LaTeX Workshop — each tool wraps its command in host-spawn
"latex-workshop.latex.tools": [
  {
    "name": "latexmk",
    "command": "host-spawn",
    "args": [
      "toolbox", "run", "--container", "LaTeX",
      "latexmk", "-synctex=1", "-interaction=nonstopmode",
      "-file-line-error", "-pdf", "-outdir=%OUTDIR%", "%DOC%"
    ],
    "env": {}
  },
  {
    "name": "xelatexmk",
    "command": "host-spawn",
    "args": [
      "toolbox", "run", "--container", "LaTeX",
      "latexmk", "-synctex=1", "-interaction=nonstopmode",
      "-file-line-error", "-xelatex", "-outdir=%OUTDIR%", "%DOC%"
    ],
    "env": {}
  },
  {
    "name": "bibtex",
    "command": "host-spawn",
    "args": ["toolbox", "run", "--container", "LaTeX", "bibtex", "%DOCFILE%"],
    "env": {}
  }
  // ... add lualatexmk, pdflatex, tectonic, etc. following the same pattern
],
"latex-workshop.linting.chktex.enabled": true,
"latex-workshop.linting.chktex.exec.path": "host-spawn",
"latex-workshop.linting.chktex.exec.args": [
  "toolbox", "run", "--container", "LaTeX",
  "chktex", "-wall", "-n22", "-n30", "-e16", "-q"
]

This allows LaTeX Workshop to communicate with LaTeX inside the toolbox. The same host-spawn → toolbox run pattern can wrap any additional builders you need (pdflatex, lualatexmk, tectonic, knitr/Rscript, Weave, pweave).
